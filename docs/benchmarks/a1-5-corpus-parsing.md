# Phase A1.5 全量解析基准

## 结论

Phase A1.5 对外部只读教材 PDF 语料执行了 MinerU → `CanonicalDocument` 基准。257 个物理条目对应 255 个唯一内容，重复内容只解析代表文件。首次运行中 244 个唯一内容成功、11 个因 MinerU `table` 条目缺少 `table_body` 而被严格 adapter 拒绝；本报告保留这组原始证据。随后只重试这 11 个失败代表，最新结果中 255 个唯一内容均生成了通过校验的 `CanonicalDocument`，表示本次流水线完成，不表示解析准确率。

本次 hardening 没有猜测表格内容：11 个失败文档共包含 13 个 `table` 条目，审计确认它们全部缺少 `table_body`，`img_path` 为空且没有可用图片资产，因此最终按 `unsupported_items` 和 `table_missing_content` warning 记录并继续处理同一文档的其他内容。

## 基准实现和可恢复性

- `benchmark-parsing` 复用现有 `mineru_runner.py`、`mineru_adapter.py` 和 `CanonicalDocument` 校验，不复制解析逻辑。
- 每个 terminal 结果立即追加并 `fsync` 到 `results.jsonl`；`run.json` 保存兼容配置、运行环境和进度。
- `--resume` 会校验 inventory fingerprint、MinerU 配置、筛选条件和保留策略，并跳过已有成功/重复结果；失败项只有在显式加入 `--retry-failed` 时才重试。
- 结果尾部出现截断或非法 JSON 时，恢复逻辑保留全部已确认的合法历史记录并修复 JSONL 尾部；运行时按 `benchmark_item_id` 使用最新记录。
- 执行固定为并发数 1，运行产物只写入被 Git 忽略的 `data/benchmarks/a1-5/`，不使用正常产品的 `data/parsing/`。
- 默认保留失败项和自动识别的坏例候选的 raw MinerU 输出；普通成功项保留 canonical JSON，清理 raw 输出。也支持 `all` 和 `none`。

## Hardening 后的增量重试

### 重试范围和审计

本次没有重新运行已成功的 244 个唯一代表文件，只对首次运行的 11 个失败代表执行 `--resume --retry-failed`。`results.jsonl` 保留首次记录并追加 11 条最新记录；按每个 `benchmark_item_id` 的最新记录聚合后，257 个物理条目全部为 terminal，255 个唯一内容均成功，2 个重复条目仍为 `skipped_duplicate`。

对 11 个失败 raw 输出逐条检查后，所有失败表格均为 `table_body` 缺失或 null、`img_path` 为空、图片资产不存在；其中 `普通高中教科书·英语必修_第三册_151-162.pdf` 有 3 个不可用表格，其余 10 个文档各有 1 个。没有样本满足 asset-only 条件，因此 `table_asset_only` 为 0。adapter 的最终规则是：有效结构化内容可与有效 `asset_ref` 共存；缺少结构化内容但有安全且存在的资产时使用 asset-only；两者都没有时跳过该条目并继续；不安全路径或其他结构性错误仍失败。

## 结果文件和限制

- 提交级汇总：[a1-5-corpus-summary.json](a1-5-corpus-summary.json)。它是从本次运行的 aggregate 生成的，不包含开发机绝对语料路径。
- 运行时的 `run.json`、`corpus-manifest.jsonl`、`results.jsonl`、canonical JSON、raw 输出和失败诊断均在 `data/benchmarks/a1-5/`，该目录被 Git 忽略，不应提交。
- 本基准没有人工标注 ground truth，因此不能衡量 precision、recall 或解析准确率；失败样本也不是准确率分母之外的“通过”。
- 结果依赖本机 GPU、驱动、MinerU 本地模型和外部语料快照；inventory fingerprint 用于后续 resume 配置校验。
- A1.5 不包含 chunking、embeddings、vector retrieval、RAG、GraphRAG、multimodal retrieval、frontend benchmark dashboard、ChatBI 或 NL2SQL；这些留待后续阶段单独设计。
