# KnowledgeScope 产品 UI 方向

## 产品定位

KnowledgeScope 是面向行业文档的知识工作区。当前产品界面聚焦于知识库和 PDF 文档的真实管理能力；未实现的解析、检索、问答和分析能力不在普通用户界面中展示。

## 信息层级

- 侧边栏只保留当前可用的“知识库”入口。
- 知识库列表优先展示名称、描述和最近更新时间，编辑、删除收纳在上下文菜单中。
- 知识库详情以名称和描述为主，文档工作区紧随其后；创建和更新时间作为次级信息。
- 不在产品界面展示开发阶段、配置状态、原始 API 健康信息或内部数据路径。

## 布局与密度

应用使用稳定的侧边栏和内容区布局，内容区保持适中的最大宽度。页面使用 4/8/12/16/24/32/40 的间距节奏，减少空泛的大卡片，让列表和文档行易于扫描。窄屏下侧边栏收缩，列表信息保持可读并允许自然换行。

## 字体、颜色与表面

使用系统字体栈，中文和英文保持一致的可读性。标题、分区标题、正文和元数据通过字号、字重、行高建立层级，而不是依赖装饰。整体采用暖白背景、白色内容表面、石墨色文字和冷灰色辅助文字；绿色只用于主操作和真实成功状态，边框和阴影保持克制。

全局颜色、表面、圆角、阴影、间距和过渡时长集中在 "frontend/src/styles/main.css" 中，并用于定制 Element Plus。避免渐变、玻璃拟态、过度阴影和无意义的大圆角。

## 导航与交互

导航名称必须对应已经可用的内容，不为未来功能预留空页面。按钮、链接和上下文菜单提供即时的 hover、active、focus 反馈；动画只用于必要的透明度、颜色或变换，并遵守 "prefers-reduced-motion"。删除等不可逆操作保留确认步骤，加载、空数据和错误状态都提供简短且可行动的反馈。

## Element Plus 使用约定

继续使用已有的 Element Plus 作为基础组件库，统一定制按钮、输入框、对话框、下拉菜单、分页和消息的视觉语言。只有在同一界面中确实重复且语义稳定时才抽取组件，不为未来功能预建抽象层。
