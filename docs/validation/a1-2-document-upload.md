# Phase A1.2 文档上传验收记录

## 验收范围

本记录覆盖当前 A1.2 已实现的 PDF 上传、文件系统存储、文档元数据 API、重复校验、删除补偿和前端文档列表。验收使用本机 Docker PostgreSQL、FastAPI、Vite 和只读真实 PDF 语料；未改写或移动源语料。

## 环境

- Python 3.12.3，`uv` 管理虚拟环境和依赖。
- PostgreSQL 16 Alpine（Docker Compose，本地开发实例）。
- Node.js/npm、Vite 开发服务器和 Chrome 浏览器。
- 应用默认单文件限制为 50 MiB；本次样本均低于该限制。
- 验收未记录或提交 `.env`、凭据、密码、Token 或其他秘密。

## 实际结果

- 在同一个知识库中通过本地 `curl` multipart 上传 9 个真实 PDF，9 个请求均返回 `201`。
- 通过文档列表和详情 API 检查持久化 `Document` 行；列表总数为 9，详情返回 `200`；公共响应未暴露内部 `storage_key`。
- 每个文件均写入 `documents/<knowledge_base_id>/<document_id>/original.pdf`，内部 `storage_key` 为应用生成的相对键；未包含源语料绝对路径或客户端 basename，源文件名只保存在 `original_filename` 元数据中。
- 9/9 个已存储文件以流式 SHA-256 与对应源文件比较，结果全部一致；源文件的 size、mtime 和 inode 在前后检查中保持不变。
- 浏览器打开真实知识库详情页后显示 9 条文档记录，刷新页面后记录仍在，状态均显示为“已上传”。
- 同一知识库再次上传相同二进制内容但更换文件名返回 `409`，且存储文件数没有增加。
- 将同一 PDF 上传到另一个知识库返回 `201`，生成不同的应用控制存储键。
- 删除至少一个文档后，API 返回 `204`，对应数据库行和文件均不存在；本次验收创建的其余文档和知识库也已清理。
- 含文档的知识库删除返回 `409`，提示先删除文档；删除完成后的临时上传/删除目录和文件均已清理。
- 额外使用无文件落盘的 multipart 输入提交伪造 `.pdf`，服务端返回受控 `415`；已有自动化测试覆盖扩展名、空文件、伪 PDF 和大小超限。

## 自动化浏览器限制

自动化环境不能向浏览器原生文件选择器注入本地文件，因此自动化流程没有执行文件选择这一步，也不将其宣称为浏览器自动化结果。

## curl 自动化 multipart 验证

自动化验收使用本机 `curl` 直接提交真实语料的 multipart 请求，完成了 9 个文件的上传、持久化、哈希、同库重复、跨库上传、删除和错误场景验证。随后通过浏览器打开并刷新真实详情页，确认了后端持久化列表和前端状态。

## 人工浏览器端到端验证

另行完成了人工浏览器流程：在浏览器 UI 点击“上传 PDF”，通过原生文件选择器选择外部教材语料中的真实 PDF；前端使用 Vue `FormData` 发起请求，FastAPI 完成上传并持久化 `Document`，新文档随后出现在真实 UI 列表中。该步骤是人工浏览器验证，不是自动化文件选择。

前端代码同时静态确认使用 `FormData` 的 `file` 字段、不手动设置 multipart boundary、阻止重复提交，并通过 Vue Query 失效文档查询。

## 范围和限制

本次没有扫描或上传约 1.4 GB 的完整语料，也没有进行解析吞吐或大规模性能基准。A1.2 只提供 PDF 原始文件上传和元数据管理；未实现 MinerU、解析、chunks、embeddings、RAG、GraphRAG、多模态检索、MinIO/S3、鉴权、病毒扫描或深度 PDF 安全分析。这些内容留待后续阶段。
